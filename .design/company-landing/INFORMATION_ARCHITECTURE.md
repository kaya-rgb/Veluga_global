## 1. 페이지 목적과 전제

- 벨루가 기업의 정체성을 전달하고, 방문자가 목적에 맞는 제품을 찾아 제품 랜딩페이지로 이동하도록 한다.
- 히어로에서 브랜드 정체성을 전달하고, 본문의 중심은 제품의 역할, 기술 역량, 실제 화면과 검증 근거에 둔다.
- ‘이해 → 연결 → 실행’은 보조 키워드로 활용할 수 있지만, 기술 강점 섹션을 추상적인 원칙 설명으로 대체하지 않는다.
- 주요 방문자는 제품 도입을 검토하는 기업 담당자, 협업 파트너, 입사에 관심 있는 사람으로 가정한다.
- 기업 아래에 벨루가 제품과 Voost가 있는 구조이며, 두 제품은 같은 위계로 소개한다.
- Voost는 출시 초기로 고객사와 실제 고객 활용 사례가 없다는 사용자 설명을 따른다.
- 한국어 콘텐츠를 먼저 제안한다. 글로벌 페이지는 언어별로 동일한 정보 구조를 유지하는 방향을 권장하며, 지원 언어와 영문 문구는 별도 확정한다.

첨부 방향성 자료의 ‘새로운 서비스 런칭 준비’는 당시의 배경 설명이다. 현재 제품 상태는 이번 대화에서 사용자가 알려준 ‘Voost 출시 완료, 고객사·고객 사례 없음’을 기준으로 한다.

## 4. 내비게이션과 방문 흐름

한 페이지 안에서 회사와 제품을 이해하고, 상세 정보가 필요할 때 각 제품 사이트로 이동하는 구조를 제안한다.

| 화면 또는 목적지 | 제안 경로 | 행동 |
|---|---|---|
| 기업 홈 | `/` | 기업 소개와 제품 탐색 |
| GNB 제품·채용 | 미연결 | 메뉴 구조만 표시. 페이지 내 점프 이동 없음 |
| Voost 시연 배치 영역 | `/#execution` | ‘도구 연결과 실행’ 상세 패널을 선택하고 해당 위치로 이동. 영상 재생은 미연결 |
| 고객 사례·관계 | `/#proof` | 사례 1개씩 노출하고 하단 dots로 전환. 와이어프레임의 미확정 사례는 배치 영역 표시 |
| 벨루가 제품 상세 | `https://veluga.app/` | 벨루가 제품 랜딩으로 이동 |
| Voost 제품 상세 | `https://veluga.ai/` | Voost 제품 랜딩으로 이동 |
| 인재풀 등록 | 페이지 내 모달, 운영 폼 URL 미정 | 구조 확인용 폼 열기. 제출·저장·전송하지 않음 |

현재 구현은 1920px 고정 데스크톱 와이어프레임이며 미리보기 배율만 조절한다. 모바일 대응과 실제 언어 전환은 미구현이다. 향후 모바일에서도 같은 메뉴와 순서를 유지하고, 실제 준비된 언어만 제공한다.

- 제품 도입 검토자: 기업 홈 → 제품 카드 → 기술 역량 및 근거 → 해당 제품 랜딩 → 제품별 도입 문의 또는 데모 요청.
- 협업 파트너: 히어로 소개 → 기술 역량 및 검증 자료 → 푸터의 기업 문의 이메일.
- 입사 관심자: 페이지를 스크롤해 인재풀 소개 확인 → 등록 폼.

## 5. 섹션별 문구 초안

### 5.1 GNB

벨루가 로고 / 제품 / 채용 / 언어 선택

‘기술’ 메뉴를 삭제하고 로고·제품·채용의 페이지 내 점프 이동을 해제했다. 현재 와이어프레임에서는 로고와 두 메뉴를 비상호작용 요소로 표시하며, 별도 목적지는 연결하지 않는다. 언어 선택 안내와 본문의 기술 역량·인재풀 섹션은 유지한다.

### 5.2 히어로

**상단 레이블:** 벨루가 소개

**제목**

> AI의 가능성을,
> 일의 변화로.

**본문**

> 필요한 지식을 찾아 쓰고, 맡긴 일이 결과로 이어지도록.
> 벨루가는 AI가 실제 업무에서 쓰이는 제품을 만들어갑니다.

히어로의 제품·기술 버튼 두 개와 하단 요약·아래로 살펴보기 영역은 삭제한다.

**모션 방향:** 제품별 UI 도식 두 개를 제거하고, 흩어진 조각들이 중앙에서 모여 정돈된 형태를 만드는 SVG/CSS 모션으로 교체했다. ‘다양한 가능성 → 일의 변화’라는 기업 메시지를 표현하는 비유이며 실제 제품 처리 과정이나 공통 엔진을 나타내지 않는다. Gray 토큰을 사용하고 제목·본문과 첫 화면 1080px를 유지한다.

8초 반복 모션에 멈춤·재생 버튼을 제공한다. 화면 밖과 비활성 탭에서는 멈추고, 동작 줄이기 설정에서는 이동 없이 정돈된 형태를 표시한다. 실제 제품 데모 영상은 별도 제품 카드의 배치 영역으로 유지한다.

**작성 근거:** 제목과 모션은 기업 관점을 전달하고, 구체적인 제품 유형과 역할은 다음 제품 소개 섹션에서 설명한다.

| 챗봇 빌더: RAG 기반으로 자료를 학습시켜 자신만의 챗봇 제작 | 내 자료를 바탕으로 답하는 챗봇 제작 |

RAG·MCP는 첫 화면에서 기능 이름 대신 역할을 풀어서 설명한다. 애널리틱스를 자동 최적화, 원인 진단, 자동 학습 기능으로 확대하지 않는다. 제품 카드에는 제작·활용·운영의 세 가지 요약과 데모 영상을 보여준다. 위 네 기능 표는 문구·영상 제작의 참고 기준이며 카드의 기능 목록으로 노출하지 않는다. 와이어프레임에는 영상 배치 영역만 두고 실제 영상 파일은 연결하지 않는다.

**현재 표시하는 역량**

| 역량 | 상세 제목 | 관련 제품과 적용 내용 |

이 표는 문서의 콘텐츠 명세이며 실제 화면에는 비교 표를 사용하지 않는다. 상세 패널 본문은 다음과 같다.

- 자료 기반 답변: ‘보유 자료를 검색·참조해 / 질문에 맞는 정보를 답변에 활용합니다.’
- 응답 흐름 설계: ‘에이전트 빌더에서 응답 흐름을 만들고, / 챗봇에 적용해 질문에 맞게 답하도록 구성합니다.’
- 도구 연결과 실행: ‘연결한 도구와 작업 환경을 활용해, / 사용자가 요청한 일을 수행하도록 합니다.’
- 사용·실행 관리: ‘각 제품의 역할에 맞춰 / AI 사용 현황을 확인하고 실행을 관리합니다.’

**확장 규칙**

- 역량은 현재의 세 가지 또는 네 가지로 고정한 기업 분류가 아니다. 현재 확인된 기능을 소개하기 위한 독립적인 항목이다.
- 새 서비스가 기존 역량을 활용하면 해당 항목의 적용 제품에만 추가한다. 관련 없는 항목에는 미지원 칸이나 빈 열을 만들지 않는다.
- 기존 역량에 속하지 않는 서비스가 추가되면 새 역량 항목과 상세 패널을 추가한다. 다른 역량의 내용을 변경할 필요가 없다.
- 적용 제품 목록은 가변 개수로 줄바꿈하며, 상세 패널은 최소 높이만 설정하고 콘텐츠에 따라 늘어난다. 미래 서비스의 이름이나 기능을 현재 화면에 미리 넣지 않는다.

기본 선택은 ‘자료 기반 답변’이다. 수직 탭의 클릭·위/아래 방향키·Home/End로 선택할 수 있다. Voost 시연 배치 영역의 `#execution` 링크는 숨겨진 실행 패널을 먼저 표시한 뒤 해당 위치로 이동한다.

하단 안내는 유지한다: ‘Voost의 내부 모델·시스템 연결 범위는 조직 환경에 따라 달라질 수 있습니다.’ RAG는 벨루가에만 표시하며, Voost의 파일 작업을 RAG로 설명하지 않는다. 애널리틱스를 자동 학습·최적화로 확대하지 않는다. 개념도는 실제 제품 캡처나 성능 검증 자료가 아니다.

**레이아웃 검토 근거:** [IBM Research의 주제별 탐색](https://research.ibm.com/topics)과 [Anthropic의 연구 분야별 소개](https://www.anthropic.com/research)에서 주제마다 내용을 독립적으로 확장하는 정보 구조를 참고했다. 이 와이어프레임의 수직 탭과 관련 제품 연결 방식은 사용자 지적을 반영해 새로 제안한 구성이다. 두 사이트의 디자인이나 기술 주장을 옮긴 것은 아니다.

**추가 자료를 받아 보강할 차별점:** 답변 품질의 평가 범위·조건·결과, 파일·프로그램별 수행 범위와 재현 가능한 시연, 권한·연결·기록의 실제 설정 화면, 비교 대상과 측정 방법이 있는 자료가 필요하다. 독자 엔진, 자체 모델, 성능 수치, 보안 인증, 공통 플랫폼은 확인 없이 추가하지 않는다.

**작성 근거:** ‘만들어가는 기업’은 회사 소개에 가깝고, 질문형 제목은 입사에 관심 있는 사람을 직접 초대하므로 채용 배너에 더 적합하다. 제목과 본문에 질문이 반복되지 않도록 본문을 초대 문장으로 정리했다. 실제 행동은 ‘인재풀에 등록하기’ 버튼으로 안내한다.
